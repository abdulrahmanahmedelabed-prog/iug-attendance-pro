# ZK Attendance Pro 42 — نظام حضور وانصراف بأسلوب BioTime 9.5

> **English summary** at the bottom.

نظام حضور وانصراف كامل لأجهزة ZKTeco (SpeedFace‑V5L، ProFace X، MB/UFace/iFace…) يعمل بنفس
الطريقة التي يعمل بها **BioTime 9.5**: الجهاز هو الذي يتصل بالخادم عبر بروتوكول **ADMS / Push**،
والبرنامج يوزّع الموظفين وقوالب الوجه والبصمة والكف على الأجهزة حسب **المناطق**، ويحسب الحضور
حسب **أوقات الدوام والورديات والجداول** مع الإجازات والعطل والعمل الإضافي، ويُخرج التقارير إلى Excel.

هذا الإصدار إعادة بناء كاملة للنسخة v41 — لماذا؟ انظر [docs/لماذا_فشلت_v41.md](docs/لماذا_فشلت_v41.md).

## التشغيل السريع (ويندوز)

1. ثبّت **Python 3.10 أو أحدث** من python.org (فعّل خيار *Add python.exe to PATH*).
2. انقر مرتين على **`start.bat`** — في المرة الأولى يثبّت المكتبات تلقائياً ثم يفتح المتصفح.
3. ادخل بـ **admin / admin** وسيطلب منك تغيير كلمة المرور.
4. (مرة واحدة، كمسؤول) شغّل **`firewall.bat`** لفتح المنافذ، و **`autostart.bat`** ليعمل الخادم تلقائياً مع ويندوز.

| ما هو | العنوان / المنفذ |
|---|---|
| واجهة البرنامج | `http://IP-الخادم:8090` |
| منفذ الأجهزة (ADMS) | `8081` و `90` (قابل للتغيير في `zkpro.ini`) |

على لينكس/أي نظام: `pip install -r requirements.txt` ثم `python run.py`.

## ربط جهاز SpeedFace‑V5L

من الجهاز: **القائمة ← الاتصال (COMM.) ← إعدادات الخادم السحابي (Cloud Server Setting)**:

| الإعداد | القيمة |
|---|---|
| Server Mode | **ADMS** |
| Enable Domain Name | إيقاف |
| Server Address | عنوان IP لحاسوب الخادم (مثال: `10.0.0.34`) |
| Server Port | `90` (أو `8081`) — نفس المنفذ في `zkpro.ini` |
| Enable Proxy Server | إيقاف |
| HTTPS | إيقاف |

> **الأجهزة متصلة بـ BioTime على المنفذ 90؟** بدون أي تغيير: الإعدادات ← «القراءة من ZKBioTime عبر واجهته»
> (`http://127.0.0.1:90` + مستخدم BioTime) فتظهر الأجهزة والموظفون والحركات فوراً. وللتحكم بالأجهزة مع إبقاء BioTime
> يعمل: «العمل جنباً إلى جنب مع ZKBioTime». التفاصيل في القسمين 6 و7 من [docs/ربط_الأجهزة.md](docs/ربط_الأجهزة.md).

خلال ثوانٍ يظهر الجهاز في **الأجهزة ← أجهزة البصمة** بحالة «متصل» مع الطراز والبرنامج الثابت
وأنواع التحقق المدعومة (وجه/بصمة/كف). التفاصيل وحل المشاكل: [docs/ربط_الأجهزة.md](docs/ربط_الأجهزة.md).

## كيف يعمل (باختصار)

* **المناطق**: كل جهاز في منطقة، وكل موظف في منطقة أو أكثر. إضافة موظف أو تعديله أو نقله أو استقالته
  تُترجم تلقائياً إلى أوامر للأجهزة (`DATA UPDATE USERINFO` / `DATA DELETE USERINFO`).
* **القوالب**: الوجه/البصمة/الكف المسجّل على أي جهاز يُرفع للخادم ثم يُرسل لباقي أجهزة المنطقة إذا كانت
  خوارزمية الجهاز متوافقة؛ وإلا تُرسل **صورة الوجه** ليستخرج الجهاز قالبه بنفسه (نفس أسلوب BioTime).
* **الحضور يُحسب لحظياً** من البيانات الخام: أي بصمة متأخرة الرفع أو تعديل في الجدول أو اعتماد إجازة
  يظهر فوراً في التقارير — لا يوجد زر «احسب» يُنسى.
* **لا تكرار**: الجهاز يعيد إرسال السجلات إذا انقطع الرد، والخادم يتجاهل المكرر.

## English summary

A BioTime 9.5‑style time & attendance server for ZKTeco terminals. Terminals connect over the
ADMS/Push protocol (`/iclock/cdata`, `getrequest`, `devicecmd`, `querydata`, `rtdata`, `registry`);
employees, face/fingerprint/palm templates and photos are distributed per **area**; attendance is
calculated on the fly from timetables, cyclic shifts, department/temporary schedules, holidays, leave,
manual punches and overtime (with approval); 13 reports export to Excel/CSV. Arabic/English UI,
roles & permissions, audit log, automatic backups.

Quick start: `pip install -r requirements.txt && python run.py` → `http://localhost:8090` (admin/admin).
Point the terminal's *Cloud Server Setting* (ADMS) at this PC, port 8081 or 90.
